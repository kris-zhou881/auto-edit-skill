# 自动剪辑制作流程

## 1. 复核参考与项目

查找用户给过的原视频、风格拆解、提示词、封面、工程和素材。先记录可访问范围与未知项；复用已验证的风格规范，不重复猜测。只在必要时补看公开视频。

## 2. 发现和筛选 GitHub Skill

在 GitHub 搜索真实仓库，记录仓库地址、Star（查询时点）、最近维护信息、许可证、README、依赖和演示可能性。按实际价值、可视化程度、痛点清晰度、演示难度、维护状态和风险比较候选，选择最适合短视频说明的一项，不按 Star 排名机械决定。

## 3. 安全审查与实测

- 阅读 Skill 全文、脚本和依赖声明；识别网络访问、遥测、自动更新、凭据、文件读取、安装钩子及高权限操作。
- 优先使用隔离项目和最小权限；固定审查过的 tag/commit。未读或未执行的代码不能标为已审查或安全。
- 不输入真实密钥、私人资料或生产数据。涉及外部写入、收费、发布或不可逆更改时先停在可审阅状态，除非用户已对该具体动作明确授权。
- 运行真实小任务并保存可核验结果、版本信息、关键日志和失败记录。准确区分静态审查、安装、实际执行和通过情况。

## 4. 脚本与镜头表

基于测试结果确定一个主要看点，写完口播/字幕文案和逐镜头表后再录制。镜头表至少包含：时间段、画面来源、实际操作、口播、字幕、剪辑/声音提示、该镜头证明的事实。前三秒同时写清画面、文案、字幕、声音和下一镜衔接；钩子必须由真实结果支撑。

## 5. 原始录屏

录制 Skill 安装页面、终端或应用实际操作及最终结果。开始前整理桌面，隐藏个人信息、令牌、通知和无关窗口；设置竖屏裁切安全区。不要后制伪造点击、运行状态或成果。保存未经剪辑的原始录屏，并记录分辨率、帧率和来源。

## 6. 剪映专业版剪辑

- 用桌面版剪映建立可再次打开的工程，导入原始录屏、口播、字幕和有权使用的素材。
- 先剪叙事，再做裁切、放大、字幕和轻量动效；操作、解说与字幕同步。镜头切换围绕信息点，不堆特效。
- 字幕按小西瓜样本中可见的清晰白字/深色底等规律处理；位置避开操作重点，最终以实机小屏可读为准。
- 音乐/音效仅用已确认免费、且许可覆盖目标平台的素材；保存来源和授权证据。音量服从口播清晰度。无法确认授权的素材不使用。
- 最终导出必须由剪映完成。若剪映要求登录、同意协议、会员或其他条件，停止在该处，保留工程和已完成内容并如实报告；不得把别的软件导出说成剪映成片。

## 7. 原创封面

先选择真实测试成果截图，再围绕一个明确收益或痛点写短标题。可借鉴样本中的数字/收益词、粗体层级和产品画面，但根据真实 UI 决定颜色与构图。输出 9:16 与 3:4 版本，保留源图或分层文件，标注实际分辨率；不得把生成界面伪装为真实截图或虚报 4K。

## 8. 交付

整理可编辑剪映工程、其依赖素材、原始录屏、最终 MP4（仅当剪映已真实导出）、两种封面、3 个标题、抖音与小红书文案/标签、仓库和版本信息、安全检查记录、许可清单、风格对照报告及可复用流程。分别标记“已完成 / 未完成 / 受阻”，列出阻碍及证据。仅待用户验收，不代替用户发布。
