# V4｜内容驱动的高级转场、UI 交互与镜头编排

此规范是抖音自动化 Skill 的新视频默认动效规则。适用于 GitHub Skill、软件教程、CLI/网页操作和科技类解说。由主 Agent 在分镜、Remotion 实现、短样验收及最终 QA 阶段加载；不改变 V3 AI 配音和动态花字、V2 自动制作/本人发布边界。真实证据、留存规则和用户当期具体约束始终优先。

## 目标与硬边界

- 目标：制作像专业科技博主的软件实测视频，而不是静态截图、循环飞入的卡片或 PPT 配音。观众应看懂实际按钮、路径、输入、输出与结果。
- 第一帧立即露出真实效果/界面（hook_visible=true），0–2 秒钩子、2–5 秒兑现；严禁用过渡、片头或炫技动画吞掉开场。真实素材作为画面主体的独占时长必须严格超过 50%。
- “每隔 3–5 秒有视觉变化”是观察检查，不是强制每 3–5 秒硬切。常规镜头尽量不超 3 秒；同一真实操作继续推进可以留长，但需要信息变化。阅读代码、步骤或关键证据时优先稳定，不为了动而动。
- 禁止假装在真实网站完成不存在的点击、输入、搜索、运行或付款；不能把模拟 UI 交互当成实测。模拟演示在画面或来源清单明确写“模拟操作/示意”，真实输出只来自授权录屏或可验证数据。敏感信息全程脱敏并跟踪遮挡。
- 禁止连续闪白、整屏震动、假景深影响文字清晰度、随机 3D 翻转、过量弹跳、重复转场、遮住平台安全区或关键 UI。每个动画都必须能回答“对应哪句旁白、帮助理解什么”。

## 1. 高级转场（按语义选，不随机选）

| 前后镜头关系 | 优先效果 | 原因与限制 |
| --- | --- | --- |
| 同一操作继续、按钮到结果 | 直接切/动作匹配（Match Cut） | 保持操作因果，避免花哨中断 |
| 从全页定位功能区 | 短距 Zoom Push / Focus Zoom | 有真实目标点、先聚焦再保留阅读时间 |
| 前后对比、旧版与新版 | Mask Reveal / 擦除分屏 | 展示对比边界，勿掩盖差异或伪造效果 |
| 章节变化、换工具 | Slide / Depth / Parallax | 可少量用空间层次；不让文字透视变形 |
| 同一信息对象在两个场景间承接 | Shared Element / 卡片连续变换 | 目标同一性明确，坐标与方向可复核 |
| UI 卡片展示为主的章节切换 | 适量 Card Flip | 仅用于信息层变换，不用于真实操作关键步骤 |

- 转场持续时间由口播停顿、阅读需求和镜头内容决定；以 30 fps 为例先试 6–12 帧的短促过渡。复杂效果经 10–15 秒短样确认后使用。
- 同一效果不可机械连续重复；优先硬切、局部焦点移动和真实操作的自然连续性。
- 禁用以随机模板、固定慢推拉、全屏花字替代实测画面的所谓“高级感”。

## 2. UI 交互动效

按内容需要挑选以下可复用组件；它们是“实现目标”，不是声称当前代码库已经实现。

- CursorPath / HoverState / ClickFeedback：鼠标按真实轨迹移动、悬停、按下，点击位置与目标按钮一致；只在画面里可见的真实动作或标注为模拟的流程中使用。
- WebScroll / FocusZoom：网页平滑滚动、聚焦 README/功能列表/结果区，保持文字可读；先确认焦点所在页面区域与录屏一致。
- InputReveal / SearchResult：输入框逐字显示、执行搜索/命令后结果展开；必须使用实测输入与输出，重演明确标注“回放/模拟”。
- ModalReveal / Accordion / TabSwitch：弹窗出现、列表滑入、卡片展开、选项卡切换；对应实际 UI 状态或清楚的示意。
- GitHubRepoTour / CodeFocus：在真实 GitHub 项目页面或 IDE 录屏上移动框选、放大重点并逐行高亮，关键 URL、命令和代码不能编造。
- CompareReveal / FlowConnector / MetricTicker：前后状态对比、流程节点和连线生长、经核验数值滚动。禁止伪造 Stars、收入、耗时、成功率或用户量。

**真实操作优先：** 优先在授权环境录真实页面/终端，再叠加不改变事实的光标、描边、局部放大和高亮；纯代码重建界面仅用于原理示意，标明身份，且不能充当真实录屏占比。

## 3. 动态信息、字幕和镜头运动

- 保留 V3 的 Qwen3-TTS MLX + Remotion kinetic/sticker/minimal 字幕规则，沿用真实口播的绝对整数帧及 captions[].segments、emphasisAt；不使用 macOS say、系统花字或静态 SRT 替代。
- 关键词以短促缩放/换色/描边/下划线高亮，数字必须来自可追溯来源；流程节点、图标和连线按讲述顺序展开。动画触发跟随语义重音，不依靠字符等分时间线。
- 允许局部推拉、跟随焦点、短距离摇移、前后景轻视差；同一镜头只设置一个主要视觉焦点。镜头运动须采用缓动与轻惯性，不能全片慢速飘动。
- 每次变化采用“定位 → 动作 → 留白让观众读懂 → 下一信息点”节奏；重要 UI 不可被字幕、贴纸、过场遮挡。
- 竖屏默认 1080×1920、30 fps，保留包内抖音平台安全区及字体对比度规范；小屏预览检查。

## 4. 内容驱动的动效编排合同

1. **脚本拆解：** 为每句旁白给出 beat_id、intent（问题/操作/解释/对比/结果）、claim、evidence_asset_id、关键词与真实口播时间窗。
2. **挑镜：** 先确定真实证据和需显示的 UI，再为每个 beat 挑选零到两个能说明信息的效果。切镜前判断：是否同操作、是否同一元素、是否需要对比、是否存在可点击目标；不符则使用直接切。
3. **产生事件计划：** 每个动效 cue 记录 beat_id、start_frame、end_frame、target_region、effect_family、effect_variant、source_type（capture/replay/schematic）、purpose、fallback 和 source/evidence。坐标以真实画面素材为准，避开字幕/安全区。
4. **统一时间轴：** 所有事件按实际配音长度和关键词重音对齐，使用同一 fps 与绝对帧。音频重录必须重算转场、鼠标、字幕和音效落点。不得为了过场拉长或挪开真实证据。
5. **实现并渲染：** 默认复用现有 Remotion 模板；需要更复杂的效果时新增可复用 React/Remotion 组件（如 TransitionDirector、CursorAction、FocusZoom、InputReveal、CodeFocus、FlowConnector），使用 useCurrentFrame 和可测试的插值/缓动，而不是每次复制粘贴一次性片段。只有本机已验可用时才选 HyperFrames 或其他引擎。
6. **记录实现状态：** “编排合同”的事件字段是拟扩展数据结构，当前 templates/remotion/timeline.mjs 只校验既有 camera、transition 数值等字段，animation.jsx 也不自动实现本文列举的全部特效。Codex 必须实际扩展渲染组件、时间轴解析/校验与测试，或明确使用已支持的基础替代并标记缺口。**仅将事件写进 JSON 或本文不等于动画已落地**。

## 5. QA 与交付硬门槛

- 先做 10–15 秒可复核样片，至少包含“真实网页/软件操作 → 一次内容相关转场 → 一次 UI 反馈或局部聚焦 → 一次与配音同步的关键词花字”，然后再制作整片。
- 渲染前校验事件帧范围、目标元素区域与素材实际状态、组件是否实现、音频/字幕时间线是否一致；不支持的字段或效果不得静默忽略并报“已完成”。
- 渲染后对首帧、转场起止帧、鼠标点击前后、弹窗状态、代码高亮、花字强调帧做连续帧核查，并在手机尺寸检查可读性、裁切、遮挡、安全区、卡顿、错位、突兀跳变和声音同步。
- 保留黑屏/冻结检测、真实素材 >50%、权属与来源检查；FFmpeg/ffprobe 与抽帧只能证明结构，不能代替真实看听或声画审查。记录已运行的测试、失败截图/时间码与实际修复，最多自动返工两轮。
- 交付待人工发布 MP4、Remotion 可编辑工程、字幕、两种封面、文案、效果/素材清单和 machine-qa.json；效果未实现、没有真实渲染或没有检查时写 not_run/blocked，不可自称“专业动效全部验收通过”。发布一律由用户本人完成。

## 协作原则

主 Agent 负责内容与视觉目标、技术真实性和最终 QA；导演 Agent 负责逐镜挑选语义匹配动效与事件计划；剪辑/Remotion Agent 负责编码、渲染、测试和提交可编辑工程。若通过 Codex 与其他 Agent 协作，只交接明确文件、责任与验收结果，不让多个 Agent 同时覆盖同一时间轴文件。
